# Звіт до Лабораторної роботи №2
**Варіант:** 0 (N = 24, дистрибутив: ubuntu:24.04)

## 1. Порівняння розмірів образів
- `lab02-naive`: 1.13 GB
- `lab02-slim` (`scratch`): ~4.1 MB

Різниця складає понад 99.6% зменшення розміру.

## 2. Кешування шарів (Рівень 2)
При зміні файлу `src/main.rs` етапи копіювання та попередньої компіляції залежностей беруться з кешу:
- `CACHED [build 4/7] COPY Cargo.toml Cargo.lock ./`
- `CACHED [build 5/7] RUN mkdir src && echo ...`

## 3. Контрольні питання

1. **Чому проміжний build-етап не впливає на розмір фінального образу при багатоетапній збірці?**
   Кожен новий `FROM` починає чисту файлову систему. У фінальний образ потрапляє лише те, що явно скопійовано через `COPY --from=build ...`, а інструменти збірки та тимчасові файли залишаються в попередньому етапі.

2. **Що станеться з кешем усіх наступних шарів, якщо змінити файл, скопійований у першому COPY?**
   Кеш цього `COPY` та всіх наступних шарів скидається (інвалідується), Docker виконує їх наново.

3. **Чому копіювання Cargo.toml окремим кроком покращує кешування?**
   Маніфест залежностей змінюється рідко. Копіюючи його раніше за вихідний код, ми кешуємо важку збірку залежностей.

4. **Чому в scratch-образ не можна помістити динамічно злінкований бінарник?**
   У `scratch` немає жодних бібліотек та динамічного завантажувача (`ld-linux`). Для запуску бінарник має бути повністю статично злінкований (під `musl`).

5. **Які інструкції створюють новий шар, а які — лише метадані?**
   - Шари ФС: `RUN`, `COPY`, `ADD`.
   - Метадані: `CMD`, `ENTRYPOINT`, `ENV`, `WORKDIR`, `EXPOSE`, `LABEL`.

6. **Як docker history допомагає оптимізувати розмір?**
   Команда показує розмір кожного створеного шару, дозволяючи знайти «найважчі» інструкції.

7. **Навіщо потрібен .dockerignore?**
   Він не дає відправляти в контекст Docker важкі каталоги на зразок `target/` та `.git/`, прискорюючи білд і не ламаючи кеш.

8. **Чим відрізняється розмір образу FROM scratch від debian:12-slim?**
   `scratch` — абсолютно порожній (0 байт), важить лише бінарник. `debian:12-slim` додатково містить системні пакети Debian (~70–80 МБ).
